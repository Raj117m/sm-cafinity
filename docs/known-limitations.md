# Known limitations

1. **Launch blocked in the build environment.** Listening on 0.0.0.0:4173 returned EPERM. Tests therefore inject requests into the real HTTP listener; they do not prove actual HTTP transport or two-device operation. The app must be launched and the device checklist run on the Mac.
2. **No production Supabase/OTP deployment.** SQLite is the implemented fallback. Synthetic account selection is explicitly demo-only. No real phone numbers or SMS verification are collected or claimed.
3. **Visual inspection pending.** React DOM interactions are tested, but real browser screenshots, touch layout, audio permissions and QR camera scans are not verified. Demo product images are bundled illustrations copied from the existing project, not café photography. They can be replaced through product image URLs.
4. **Full settlement only.** Partial payments, item-level refunds, arbitrary manager write-offs and payment gateways are absent. An owner can void an incorrect whole payment, retain history, reverse earned coins and re-record the correct payment. Existing redemption stays reserved for that corrected bill.
5. **Counter payment is a second step.** Counter entry sends an unpaid order directly to NEW; staff then opens its bill and records verified payment. There is no combined pay-and-send wizard. Preparation and payment remain independent.
6. **Options use a small advanced editor.** Variations/add-ons are supported with authoritative prices, but owner configuration currently uses a validated JSON field. Ingredient requirements attach to the product, not an option; selecting an option does not bypass a required ingredient.
7. **Demo-only customer creation.** Two test accounts are seeded. There is no public self-registration flow until verified identity is connected.
8. **Shared bills require participation.** A new browser can see a table bill only after placing an order into it. This is intentional privacy protection against someone merely knowing a table URL. Session access lasts 24 hours; there is no automatic identity association by table.
9. **Historic demand estimates use current recipe links.** Historical financial item prices are snapshotted. Ingredient-demand estimates can change if an owner changes product dependencies and are labelled estimates.
10. **Initial migration only.** Version 1 creates the real schema. Upgrade orchestration beyond the initial version needs an explicit future migration runner.
11. **Local infrastructure.** The laptop must remain on and reachable. The app is not an offline-first multi-master system. SSE loss triggers reconnection and authoritative resync; it does not permit offline order confirmation.
12. **Bounded operational design still needs production hardening.** Snapshot responses include the staff's full transaction history, passwords use synchronous scrypt and there is no expired-session cleanup job yet. Appropriate for the scoped demo; pagination, retention, independent security review and longer-duration load tests are still needed before sustained commercial use.
13. **Fresh dependency install unverified.** Network restrictions prevented npm registry access. The source build passed with compatible existing local dependencies. The included compiled application runs using Node built-ins without npm install.
